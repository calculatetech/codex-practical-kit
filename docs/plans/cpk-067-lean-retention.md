## Decision Log


- Decision: Keep useful current decisions in existing owners and let Git retain prior versions.
  Rationale: Another archive, receipt database, or historical source index repeats Git and increases context use.
- Decision: Maintain at most one reusable summary per needed topic and read old Git sources only for a current question.
  Rationale: Reopening every completed task and adding immutable summary revisions creates unnecessary growth. Preserve unresolved constraints and direct source provenance.
- Decision: Put cleanup triggers and artifact ownership in Delivery Lifecycle.
  Rationale: Task start, planning, consumer completion, and delivery already supply the needed maintenance points. No scheduler is needed.
- Decision: Compare historical capture blobs by exact event identity and bytes.
  Rationale: Live-file deduplication recreates retired captures. Event-only or content-only suppression loses new evidence. Native Git provides the historical source.
- Decision: Use inherited bytecode suppression and Python's in-memory compiler in both launchers.
  Rationale: The same unit and syntax checks can run without persistent build output or a new dependency.
- Decision: Keep this specification for the current unintegrated handoff.
  Rationale: Publication still needs the current scope. Retire it when its final current consumer finishes.
